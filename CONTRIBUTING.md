# Правила командной работы ООО «ГУДОК»

## Основная ветка и изменения

- `main` хранит согласованный комплект документов.
- Изменения готовятся в тематических ветках: `docs/uc-01`, `docs/uc-02`, `docs/uc-03`, `docs/uc-04`, `fix/uml-links`.
- Коммиты объясняют результат: `Уточнён альтернативный поток UC-02`, а не `fix` или `update`.
- Коммит и авторство должны отражать **фактического** исполнителя, а не назначенную в отчёте роль.

## Pull Request и взаимная проверка

Каждый запрос на слияние содержит: цель, связанные ФТ и UC, перечень файлов, описание проверки, изменения по замечаниям. **Проверку делает другой участник**: автор не должен подтверждать собственную работу как чужое ревью. Только после проверки и одобрения изменения включаются в `main`.

Пример PR: `docs: уточнить основной и альтернативные потоки UC-02`.

## Актуальность документов

Содержательные изменения сначала вносятся в Markdown (`docs/README.md`, `docs/md/`). Перед сдачей обновляется соответствующая Word-версия. Исходники Mermaid в `docs/draw/`, диаграммы в Markdown и изображения должны обновляться согласованно. Диаграммы Mermaid находятся непосредственно в Markdown.

## Текущий статус

Документация и примерные зоны ответственности предварительно подготовлены централизованно. Отдельные Git-коммиты, фактические личные проверки и согласование преподавателем ещё нельзя считать выполненными без соответствующих свидетельств.
