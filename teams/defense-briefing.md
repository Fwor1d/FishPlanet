# Краткая подготовка команды к защите ООО «ГУДОК»

> Использовать как материал для обучения, а не как замену фактически выполненных действий.

## Общая версия ответа (40 секунд)

«Наш учебный проект — система учёта перемещений рыб между бассейнами. Она предназначена для сотрудников рыбной фермы. Программа должна учитывать вид и количество рыб, время переплыва и момент события. Работники просматривают счётчик и историю, а управление процессом доступно только техническому администратору. По интервью бюджет — миллион рублей, срок — 60 дней. Мы описали четыре варианта использования и построили диаграммы; способ автоматической регистрации и команды оборудования требуют уточнения».

## Шейкин Д. М. — UC-01 (счётчик)

**Понимать:** выбор бассейна назначения и периода, подсчёт рыб по видам. **Основной поток:** открыть счётчик, задать условия, запросить данные, увидеть количество. **Альтернативы:** начало интервала позже конца (ошибка) или нет событий (нулевой результат). **ФТ:** 01, 02.

**Что спросит преподаватель:** что показывает счётчик? Почему ноль — допустимый результат? Вносит ли просмотр изменения? Ответ: количество рыб по видам, отсутствие событий не ошибка, данные не меняются.

## Амелякин М. И. — UC-02 (интервалы)

**Понимать:** список периодов с началом и концом, просмотр перемещений за выбранный период. **Альтернативы:** интервалов нет или внутри выбранного интервала нет записей. **Связь:** можно перейти в UC-03. **ФТ:** 03.

**Что спросит преподаватель:** почему переход в UC-03 не `include`? Потому что открывать детали необязательно: UC-02 может завершиться показом списка.

## Гогичашвили Г. Л. — UC-03 (подробности)

**Понимать:** один выбранный переплыв, вид рыбы, количество, бассейн назначения, точное время, время переплыва. **Альтернативы:** запись стала недоступна либо не загрузились сведения. **ФТ:** 01, 04.

**Что спросит преподаватель:** в чём отличие от UC-02? UC-02 — список интервалов и перемещений, UC-03 — сведения об одной записи.

## Качурский Е. А. — UC-04 (управление)

**Понимать:** только технический администратор инициирует допустимое управление, система проверяет права и сообщает итог. **Альтернативы:** отказ в доступе, ошибка операции, отмена подтверждения. **ФТ:** 05.

**Что спросит преподаватель:** какие команды отправляются оборудованию? Нельзя утверждать: заказчик их не назвал, это вопрос для согласования. Почему у сотрудника нет такой функции? Ограничение прямо дано в интервью.

## ПЗ № 3 — UML за 30 секунд

Общая диаграмма Use Case показывает **кто** и **что** может делать; последовательности — **в каком порядке** действующее лицо обменивается сообщениями с системой. Акторы находятся за границей системы, БД не выступает внешним актором. Ветвь `alt` показывает альтернативные исходы. Диаграммы Mermaid доступны в [ПЗ № 3](../docs/md/pz3-uml.md); строгое UML-представление и редактируемые исходники — в [draw](../docs/draw/).

## ПЗ № 4 — Git за 45 секунд

Git — локальная система версий, GitHub — площадка для обмена ими. `clone` получает репозиторий, `add` подготавливает изменения, `commit` фиксирует их, `push` публикует, `pull` обновляет локальную ветку. Тематическая ветка отделяет изменения, PR предлагает включить их в `main`; другой участник должен проверить PR. `docs/README.md` — полный отчёт, `docs/md/` — отдельные отчёты, `docs/draw/` — редактируемые диаграммы.

### Проверка готовности команды к защите

Каждый должен открыть свой UC, объяснить один успешный и один ошибочный сценарий, назвать номер ФТ, показать собственное реальное изменение в Git (если уже сделал) и честно ответить, что не подтверждено заказчиком.
