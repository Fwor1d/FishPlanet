# Администрирование перемещений

## Разработчик

За UC-04 по распределению команды отвечает Качурский Е. А. Автор коммитов демонстрационной реализации в этой ветке — `Fwor1d`.

## Назначение

Модуль проверяет предусловие доступа технического администратора, показывает бассейны и обрабатывает подтверждение либо отмену имитационного запроса для выбранного бассейна.

## Связанные требования

ФТ-05, [UC-04](../../docs/md/pz2-use-cases.md#вариант-использования-uc-04-управление-процессом-перемещения), [SD-04](../../docs/draw/sd-04.mmd). Право на управление проверяется на входе в сценарий. В самом SD-04 альтернативы А1 и А2 соответствуют ошибке выполнения и отмене.

## Входные данные

ID пользователя, ID бассейна, действие `simulate`, подтверждение и файл UTF-8 JSON с массивами `users` и `pools`. По умолчанию используется `demo.json` из каталога модуля. Роль берётся из справочника по ID пользователя.

## Результат

`get_control_options(data, user_id)` возвращает доступные бассейны и действие. `process_request(data, user_id, pool_id, action, confirmed, simulate_failure=False)` возвращает статус `simulated`, `cancelled` или `failed`. При отказе в доступе функция выбрасывает `PermissionError`, при некорректных данных — `ValueError`. В консоли успех и отмена дают код 0, отказ и имитированная ошибка — код 1, недопустимый ввод — код 2.

## Запуск

Из корня репозитория, Python 3.12, стандартная библиотека. На Windows вместо `python3` можно использовать `py -3.12`.

```sh
python3 modules/admin-control/main.py 1
python3 modules/admin-control/main.py 1 --pool-id 2 --confirm
python3 modules/admin-control/main.py 1 --pool-id 2 --confirm --simulate-error
python3 modules/admin-control/main.py 1 --pool-id 2 --cancel
python3 modules/admin-control/main.py 2 --pool-id 2 --confirm
python3 modules/admin-control/main.py 1 --pool-id 0 --confirm
```

Команды показывают меню, успешную имитацию, ошибку выполнения (А1), отмену (А2), недоступность управления для сотрудника и ошибку ID соответственно. Если передан бассейн и пропущены `--confirm` и `--cancel`, консоль запрашивает подтверждение. Опция `--data путь.json` подключает другой справочник.

## Текущее состояние

Роли и бассейны заданы в учебном справочнике. Указанный в консоли ID выбирает демонстрационную учётную запись без входа в систему. Единственное действие `simulate` работает в памяти и возвращает результат обработки запроса. Интеграция с оборудованием потребует согласования команд с заказчиком.

## Общий формат данных

Корневой объект JSON соответствует словарю Python. Каждый модуль использует только нужные ему массивы. В [demo.json](demo.json) приведён полный пример.

| Массив | Поля объекта |
| --- | --- |
| `pools` | `id`, `name` (название бассейна) |
| `movements` | `id`, `species` (вид), `count` (целое число рыб от 1), `destination_pool_id` (ссылка на `pools.id`), `occurred_at` (время события), `duration_seconds` (целое число секунд от 0) |
| `intervals` | `id`, `start`, `end` (начало и конец периода) |
| `users` | `id`, `role` (`technical_admin` или `employee` в демонстрационных данных) |

Идентификаторы — положительные целые числа, уникальные внутри массива. Названия и виды — непустые строки. Время записывается в ISO 8601 с секундами и обязательным часовым смещением `Z` или `±HH:MM`. Допускается до шести цифр дробной части секунды. Время сравнивается с учётом смещения. Обе границы интервала включены, начало может совпадать с концом. Ключи используют `snake_case`.
